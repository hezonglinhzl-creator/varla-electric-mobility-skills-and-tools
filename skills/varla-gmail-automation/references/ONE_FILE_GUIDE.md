# Varla Gmail Automation：其他项目使用指引

## 这个技能做什么

用于 Varla KOL 的 Gmail 工作流：检查 `info@varlascooter.com` 登录状态、读取既有邮件线程、基于知识库起草或发送回复、在原线程添加合同/内容附件，以及核对已发送结果。

## 安装

1. 将 `varla-gmail-automation.skill` 安装到目标 Codex 项目。
2. 在目标电脑准备 Google OAuth 的 `credentials.json` 和独立的 `token.json`。
3. 不要把凭据、token、邮箱导出或本地数据库放进项目仓库。
4. 首次使用时授权 `info@varlascooter.com`，并先运行账户验证。

## 每次回复的固定顺序

1. 读取完整邮件线程，确认最后一封外部邮件和已有承诺。
2. 涉及车型、佣金、优惠券、合同、订单、库存、发货、Tracking 时，先查询该项目的知识库与订单/物流状态。
3. 已有会话必须在同一个 Gmail 线程回复，不能新开主题。
4. 正文使用 UTF-8 文本文件，真实分段：问候、短句组、署名之间空一行。
5. 先建草稿；只有用户明确说“发送”后才发送。
6. 发送后核对发件人、收件人、线程 ID、邮件 ID 和附件清单。

## 合同和附件规则

- 已完成并签署的 DOCX 合同有效，不默认要求 PDF 转换或二次签字。
- 合同文件名：`YYYY-MM-DD_Varla_KOL_Agreement_车型_创作者邮箱.docx`。
- 不使用 `TEST`、`TEST_ONLY` 或测试编号作为创作者附件名。
- 发合同前检查姓名、邮箱、车型、车型 Hashtag、签名栏和文件名。
- 需要时将合同与内容要求作为两个独立附件发送。

## 发货回复规则

签署合同、完整收货信息、车型和数量确认、库存确认、订单创建都完成前，不承诺具体发货日期。

订单发货后，向创作者说明承运商 Tracking 会自动发送。

## 避免乱码

正文中不能出现可见的 `\\n` 或 `\\r\\n`。该技能会拦截此类正文；请在文本文件中输入真实换行后重新发送。
