# Varla KOL 总控台｜小白使用说明

这是一套只在当前电脑运行的 KOL 邮件辅助工具。它负责识别、分类、生成预览和安全检查，但不会因为启动、识别、刷新或生成预览而自动发送邮件。

> **最重要的规则：回复、转发和添加 KOL 标签都必须由你逐条检查，并亲自点击确认。**

## 一键启动

推荐直接双击桌面上的 **Varla KOL 总控台** 快捷方式。

如果桌面快捷方式缺失或项目位置发生变化，双击项目根目录中的
`INSTALL_DESKTOP_LAUNCHER.bat` 即可重新安装。也可以直接双击项目根目录中的
`START_KOL_COMMAND_CENTER.bat` 启动。

1. 双击桌面上的 `Varla KOL 总控台`。
2. 第一次启动可能需要准备本地运行环境，请耐心等待，不要连续双击。
3. 启动成功后会自动打开浏览器，地址是：
   `http://127.0.0.1:8791/`
4. 如果浏览器没有自动打开，把上面的地址复制到浏览器。

启动成功只代表本地页面已打开，不会自动扫描 Gmail，也不会自动回复或转发。

## 先看状态，再开始工作

页面打开后，先确认以下状态：

| 项目 | 正确状态 |
| --- | --- |
| 运行地址 | `127.0.0.1:8791` |
| 本地模式 | 开启 |
| 人工模式 | 开启 |
| 自动模式 | 关闭 |
| 全部暂停 | 未暂停时才可执行写操作 |

如果 Gmail、回复助手、合同更新器或飞书显示“不可用”“漂移”或“需检查”，先不要发送。点击“系统自检”查看具体是哪一个组件需要处理。

## 常用按钮是什么意思

### 开始识别

手动读取最近 30 天内与 KOL 合作、邀约、赞助、联盟佣金、内容创作或产品评测相关的 Gmail 候选线程，最多读取 50 个候选结果，再读取完整线程进行分类并生成任务。不发送、不转发、不自动添加 `KOL` 标签；唯一例外是明确命中的 SEO 外链、客座文章、链接插入或网站位推销，系统会把精确 Gmail 线程移入可恢复的垃圾邮件、为该精确发件人建立 Gmail 垃圾箱过滤器并写入审计。以后来自同一地址的邮件由 Gmail 直接进入垃圾箱，即使总控台没有打开也生效。

普通 KOL 邀约、创作者自荐、一般 no-reply 简报和无法确定的营销邮件不会自动进入垃圾邮件。Gmail 操作前必须同时核对 `info@varlascooter.com`、线程 ID、最新外部消息 ID 和发件人；如果 Varla 同事之后回复过，自动停止并转人工。

识别范围由后端固定，网页不能扩大到整个邮箱。纯 KOL 合作进入 KOL 组；售前、订单物流和售后问题仍进入对应部门组。

顶部 Gmail、飞书、本地数据库、回复助手和合同更新器状态卡均可点击。Gmail 和任务卡中的“在 Gmail 中查看”会打开邮箱；本地数据库、回复助手和合同更新器会打开 Windows 文件资源管理器中的受控位置，网页不能提交任意文件路径。

点击“重新检查外部服务”可分别检查 Gmail、回复助手和合同更新器。飞书不可用时继续使用本地知识库；回复助手文件发生变化时会显示“版本待确认”，邮件读取和分类仍可继续，但回复前应先完成组件检查。

### 生成并预览

读取当前组的本地知识，生成一份可检查的回复预览。此时仍然不会发送。

### 保存修改

修改回复后先保存。保存时系统会重新做安全检查；如果出现知识冲突、危险承诺、邮件头注入或任务已变化，保存会被停止。

### 重新分类

分类不对时，选择正确分组并填写调整原因。重新分类后要重新生成预览。

### 确认 KOL 标签

只给确认过的纯 KOL Gmail 线程添加已经存在的 `KOL` 标签，不创建相似标签。

### 确认回复

再次显示收件人、完整正文、知识版本和风险提示。只有你点击第二次确认后，系统才会重新读取最新线程并执行回复。

### 确认转发

再次检查线程并按固定白名单推导部门邮箱。页面文字、邮件正文或手工输入都不能改变收件人。

### 忽略 / 人工处理

“忽略”会结束当前任务；“人工处理”用于风险、知识不足、分类冲突或需要人工判断的情况。

### 全部暂停

立即阻止识别、同步和任务写操作。只读查看与系统自检仍可使用。处理异常、备份数据或暂时离开时可以先暂停。

## 四个工作分组

| 分组 | 典型内容 | 可执行动作 |
| --- | --- | --- |
| KOL 合作 | 达人合作、置换、佣金、内容交付、合作跟进 | 人工确认后回复；纯 KOL 可确认 `KOL` 标签 |
| 售前 | 价格、库存、购买、运费、产品参数 | 只允许转发到 `support@varlascooter.com` |
| 订单物流 | 订单状态、追踪号、已发货未签收 | 只允许转发到 `support@varlascooter.com` |
| 售后 | 故障、刹车、维修、损坏、退换、客服问题 | 只允许转发到 `customer@varlascooter.com` |

一封邮件同时包含 KOL 和客服问题时，会保留主组与次组，不能把客服问题伪装成纯 KOL 回复。

## 哪些情况一定会停下来

出现以下任一情况时，不要尝试绕过：

- 价格或佣金变更、免费送车、发货承诺、合同条款；
- 退款、保修、法律、隐私、付款争议、个人敏感信息；
- 起火、爆炸、受伤或其他安全事故；
- 收件人不在白名单、内部邮件循环或发件人异常；
- 预览后又收到新消息、任务版本变化或重复点击；
- 知识缺失、知识冲突、模板或子 Skill hash 漂移；
- Gmail、飞书或本地组件返回不确定结果。

正确做法是刷新任务、重新识别或转为人工处理。不要因为着急而复制地址到其他输入框。

## 固定收件人白名单

系统只允许：

- 回复纯 KOL 邮件时，回复当前线程核验后的原始外部发件人；
- 售前、订单物流转发到 `support@varlascooter.com`；
- 售后转发到 `customer@varlascooter.com`。

没有自由填写收件人的入口，这是安全设计，不是功能缺失。

### 需要变更部门邮箱时

部门邮箱不能在页面临时修改，也不能从邮件正文复制。**这是跨多个模块的生产级变更，小白用户不要自行修改。**

目前路由信息至少分布在以下消费者中，不能只改其中两处：

- `app/classifier.py` 中的 `GROUP_ROUTES`：分类结果建议的部门；
- `app/gmail_gateway.py` 中的 `FORWARD_RECIPIENTS`：Gmail 网关最后允许的转发白名单；
- `app/main.py`：API 返回给页面的路由与 capabilities；
- `app/production_services.py`：人工重新分类后写入的路由；
- `app/web/index.html`：页面上的静态部门说明。

必须由技术人员统一检查并修改所有消费者。推荐先把部门路由重构成单一受信任来源，再让分类、API、工作流、Gmail 网关和页面共同读取，减少以后漏改。

变更后还要更新所有相关快照、固定评估集、端到端测试和页面测试，运行完整测试，由负责人审核提交；之后重新执行安装验证和真实本地启动验证，确认页面状态仍是本地模式、人工模式、自动模式关闭。只改页面显示、只改某个 Python 文件，或把新邮箱写进邮件模板，都不会安全地获得转发权限。

## 飞书同步与本地知识

- 本地知识库是日常运行主数据；飞书不是每次回复的实时依赖。
- 自动检查间隔是 **72 小时**，未到时间不会高频同步。
- “立即同步”是人工触发的一次检查。
- 飞书或 Lark 不可用时，页面会显示真实失败状态，并继续使用最近一次已验证的本地缓存。
- 同步失败不代表可以忽略知识版本或模板漂移；发现漂移必须先人工审查。

## 数据、日志和知识放在哪里

把下面路径粘贴到 Windows 文件资源管理器地址栏即可打开。

| 内容 | 位置 |
| --- | --- |
| 运行数据总目录 | `%LOCALAPPDATA%\VarlaKOLCommandCenter` |
| 任务和审计数据库 | `%LOCALAPPDATA%\VarlaKOLCommandCenter\command-center.sqlite3` |
| 飞书本地缓存 | `%LOCALAPPDATA%\VarlaKOLCommandCenter\knowledge-cache` |
| 服务日志 | `%LOCALAPPDATA%\VarlaKOLCommandCenter\logs` |
| 备份目录 | `%LOCALAPPDATA%\VarlaKOLCommandCenter\backups` |
| 服务 PID 和启动信息 | `%LOCALAPPDATA%\VarlaKOLCommandCenter\runtime` |
| 项目内置知识包 | 项目根目录下的 `knowledge` 文件夹 |
| 审计记录 | 页面左侧“审计记录”，底层保存在本地数据库 |

日志文件名通常是 `server-日期时间.out.log` 和 `server-日期时间.err.log`。排查启动失败时优先看最新的 `.err.log`，不要把 OAuth token、凭据文件或完整邮件内容发给无关人员。

## 备份与恢复

### 备份

1. 在页面点击“全部暂停”。
2. 确认没有任务正在执行。
3. 在 `%LOCALAPPDATA%\VarlaKOLCommandCenter\backups` 下新建一个带日期的文件夹。
4. 把运行数据总目录中的数据库、知识缓存、运行状态和日志复制进去。
5. 保留原文件，不要剪切，不要批量删除旧备份。

### 恢复

1. 先暂停系统，并确认本地服务已经停止。
2. 先把当前数据复制到一个新的日期备份文件夹。
3. 只从一份明确、完整、已验证的备份恢复。
4. 不要在服务运行时直接覆盖 SQLite 数据库，也不要混用不同日期的数据库与 `-wal`、`-shm` 文件。
5. 恢复后重新启动，先检查本地/人工/自动模式，再运行系统自检。

如果不确定服务是否已经停止，或不知道应该恢复哪些文件，请停止操作并让技术人员处理，不要尝试删除整个目录。

### 子 Skill 的备份与逐个恢复

总控的本地备份根目录是：

`%LOCALAPPDATA%\VarlaKOLCommandCenter\backups`

`skills-lock.json` 记录受信任子 Skill 的文件清单、SHA256，以及存在时的逻辑备份定位。例如 `root_id=varla_local_backups`、`name=某个备份名` 对应上面备份根目录中的同名文件夹。

恢复时必须遵守：

1. 一次只处理一个子 Skill，不要整体覆盖 `%USERPROFILE%\.codex\skills`。
2. 先查看该 Skill 在 `skills-lock.json` 中是否有明确 `backup` 定位；没有定位时不要猜路径，使用它自己的保留备份安装器重新安装。
3. 只恢复清单中列出的明确文件，并保留当前版本的独立备份。
4. 恢复后逐个计算文件 SHA256，与批准的清单或目标备份记录核对。
5. 运行“系统自检”和该子 Skill 的独立测试；Gmail、回复助手、合同更新器应分别验证，不能用其中一个成功代替另外两个。
6. 出现 `drift`、`untrusted` 或未知文件变化时保持禁用，先人工审查来源、差异和测试结果。
7. **未知漂移绝不能通过写入新 lock、健康检查或“重新设基线”来消除。** 只有负责人明确批准后，才能执行单独的接受动作更新锁定记录。

## 常见问题

### 点击确认后提示任务已变化

说明另一页面、刷新操作或新邮件改变了任务。关闭确认框，刷新任务，重新生成并核对预览。

### 连续点击会不会重复发送

系统有页面锁、版本检查和持久化幂等保护。第二次点击会被拒绝或返回已完成；仍然不要故意连续点击。

### 飞书不可用还能工作吗

可以继续使用最近一次已验证的本地知识缓存，但页面会明确显示飞书不可用。需要最新政策或发生知识冲突时必须等待人工处理。

### 关闭网页会不会发送

不会。关闭或刷新页面都不是确认动作。已经保存的任务、草稿状态和审计记录保存在本地数据库。

### 能不能开启自动回复

不能定时自动扫描、回复或转发。本版本仍固定为人工开始、人工预览、人工确认，`auto_mode` 保持 `false`。唯一持续授权是：用户手动点击“开始识别”时，精确命中 `vendor_promotion` 或本地精确发件人黑名单的邮件可直接移入可恢复的 Gmail 垃圾箱，并为该发件人建立精确 Gmail 过滤器；不会建立宽泛关键词过滤器，也不会永久删除。
